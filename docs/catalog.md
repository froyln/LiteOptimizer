# Optimization catalog

Policy updated 2026-10-14: server/shared simulation retains strict vanilla parity; client-only
behavior changes are allowed with documented configurable tradeoffs and measured gain.
New/reopened rows must state client versus shared/server scope, player-action/network boundary,
and intended visual differences. Historical pixel/RNG rejection notes below describe the former
strict-client-parity policy; they remain evidence, not automatic rejection under the new policy.
Reevaluation does not restore removed code or establish gain/compatibility. See `AGENTS.md`.

Every candidate, whether it ships or not. Columns: **applies** = the 1.12.2 class/method
(verified in the decompiled source unless marked `?`); **parity** = risk that game state /
pixels change (`low`, `med`, `high`) with the reason; render/memory placement alone does not
establish safety. Distinguish mandatory server parity from intentional client differences;
**collides** = installed litemods that also mixin the target class (from the class lists of
`~/.local/share/PrismLauncher/instances/1.12.2 test ai/minecraft/mods/1.12.2/` — all of them
use `@Inject`/`@Redirect` on the classes we care about, none `@Overwrite`, so co-existence
is fine as long as we do the same); **gain** = which benchmark world should move
(`docs/methodology.md` §2) — `pending profiles` until the baseline profiles exist; **effort**
S/M/L; **status** = `candidate` / `argued` / `shipped (<sha>, <numbers>)` / `rejected (<why>)`.
Rows whose source says **audit X** come from reading the vanilla code directly — `docs/vanilla-audit.md`
has the method-by-method evidence (file:line, what runs per execution, why the fix is parity-safe).

Release-default gate (2026-10-15): historical `shipped` labels do not enable an optimization.
Only measured candidates with state parity or a documented client-only tradeoff are default-on:
`sodium`, `model_display_lists`, `tile_entity_frustum`, `camera_visgraph_cache`,
`blockstate_property_storage`, `baked_quad_dedup`, `property_hashcode_cache`,
`hopper_entity_lookup`, and `structure_lookup_index`. Every other implemented key defaults off,
and a persisted `true` is normalized off until its isolated gain evidence is recorded.
