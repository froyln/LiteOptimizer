# Optimization catalog

Every candidate, whether it ships or not. Columns: **applies** = the 1.12.2 class/method
(verified in the decompiled source unless marked `?`); **parity** = risk that game state /
pixels change (`none` = render- or memory-only, `low`, `med`, `high`) with the reason;
**collides** = installed litemods that also mixin the target class (from the class lists of
`~/.local/share/PrismLauncher/instances/1.12.2 test ai/minecraft/mods/1.12.2/` — all of them
use `@Inject`/`@Redirect` on the classes we care about, none `@Overwrite`, so co-existence
is fine as long as we do the same); **gain** = which benchmark world should move
(`docs/methodology.md` §2) — `pending profiles` until the baseline profiles exist; **effort**
S/M/L; **status** = `candidate` / `argued` / `shipped (<sha>, <numbers>)` / `rejected (<why>)`.
Rows whose source says **audit X** come from reading the vanilla code directly — `docs/vanilla-audit.md`
has the method-by-method evidence (file:line, what runs per execution, why the fix is parity-safe).

## Lighting

Newlight (installed, MIT, `nessiesson/newlight`) hooks (injects/redirects — it has no
`@Overwrite`, verified 2026-09-18) `World.checkLight`, `Chunk` relighting, `ExtendedBlockStorage`,
`SPacketChunkData`, `ChunkProviderServer`, `AnvilChunkLoader`, `WorldServer`,

## Rejected on principle (so nobody re-proposes them)

Anything that changes RNG consumption, entity/TE iteration order, float math order, update
order, spawn results, or item/XP merging rules. Server-only concerns (dedicated server) are
out of scope: LiteLoader is client-only; the integrated server counts.
